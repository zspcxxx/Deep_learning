参数含义与实现说明

按配置页分组说明含义、默认值、改了会发生什么。 与看板「模型实验」(/translator/ · tiny_translator) 对照阅读时，优先看下面的 实现差异一节。

这个项目在做什么

任务是中英互译（English ↔ Chinese）：同一套 Encoder–Decoder Transformer，靠源端 方向标签区分「英→中」还是「中→英」。词表是中英联合 SentencePiece BPE， 不是英文按词、中文按字的两套词表。

输入

源句经 BPE 切成子词；最前面加 <en2zh> 或 <zh2en>，末尾 </s>。

模型

手写 Transformer（正弦位置编码、多头注意力、Pre-LN、因果掩码、可选共享输出层）；双语共用一份嵌入。

目标

标签平滑交叉熵；验证/测试用 sacrebleu（中文 zh 分词、英文 13a）。

产出

runs/<时间>_<名称>/：配置、SPM 模型、history、best/last 权重；也可用 CLI 同目录训练。

建议用法先套预设「快速试跑」跑通互译；再切「Jetson 互译」或换 news-commentary 做正式实验。一次只改一类旋钮，并与「模型实验」的结果区分开（任务与分词都不同，BLEU 不可直接横比）。

与 tiny_translator（模型实验）的实现差异

两者都是「网页上配置 → 后台训 Transformer → 验证试译」，但定位不同： 模型实验是短句单向英→中教学 Demo；本项目是可 CLI / YAML / Web 共用的中英互译完整流水线。

维度模型实验 tiny_translator本项目 bilingual_mt

方向标签如何工作

选 direction=both 时，每条平行句 (en, zh) 会展开成两条训练样本：

  • 源 = <en2zh> + BPE(en) + </s>，目标 = BPE(zh)（教师强制时带 <s>…</s>）
  • 源 = <zh2en> + BPE(zh) + </s>，目标 = BPE(en)

标签作为 SentencePiece 的 user_defined_symbols 写进词表，不会被切碎。 推理时必须指定方向，模型才能知道该往哪边译——这是相对 tiny「永远英→中」多出来的约定。

为什么用联合 BPE

  • tiny：中文按字 → 词表随汉字集合涨，英文稀有词易变 <unk>；实现直观，适合课内讲解。
  • 本项目：BPE 把高频片段压成子词，英文形态变化与中文词块都能共享容量；互译时源/目标在同一嵌入空间，更接近常见 NMT 配方。

代价：调试时不如「一字一符」好读；vocab_size 过小会触发「字符集 > 词表」错误（训练端会自动抬升）。

网页上的三步

  1. 配置：确认数据集就绪；调数据 / 结构 / 训练 / 解码，或套用预设；「检查配置」估算句对、参数量与总步数（完整 SPM 在真正开始训练时构建）。
  2. 训练：后台线程：准备数据 → 训 SPM → 训练；曲线含损失 / BLEU / 学习率；互译时每轮可看英→中与中→英 BLEU；可停止并保留权重。
  3. 验证：选运行；选方向做交互翻译；在 test/val 上批量评估（报告平均 BLEU 与分方向分数）。

一、数据参数

运行名称 name（默认 bilingual）

结果目录：project/bilingual_mt/runs/<时间戳>_<名称>/。与 tiny 的 runs 互不覆盖，请用能区分实验的名字（如 jetson_both、nc_en2zh）。

数据集 dataset（默认 news-commentary）

对应 data/<名称>.tsv，每行 英文<Tab>中文。内置与模型实验相同的三套可下载语料；设备上通常已软链自 tiny_translator/data。

  • cmn-eng：短句，适合快速试跑（与 tiny 默认语料一致）。
  • news-commentary：约 31 万对新闻评论，本项目默认；句子更长，请配合足够的 max_*_len。
  • ted2020：口语演讲句对。

翻译方向 direction（默认 both）

取值训练样本何时用
both每句对 → 两条（英→中 + 中→英）默认；要互译能力时
en2zh仅英→中只关心中文生成；样本量为 both 的一半
zh2en仅中→英只关心英文生成

both 时每个 epoch 实际优化步数约为「句对数 × 2 / batch_size」。与 tiny 比，同样原始句对数下这里步数更多。

最多使用句对数 max_pairs（默认 0 = 全部）

对原始平行句对截断（在展开方向之前）。烟雾测试建议 2k–15k；Jetson 正式跑可用预设里的 8 万上限。

中文统一为简体 zh_simplified（默认开启）

与 tiny 相同：用 zhconv 转简体，避免繁简各占词表配额。互译时源端中文、目标端中文都会受益。

源端最大子词数 max_src_len（默认 64）

单位是 BPE 片数（含方向标签与结束符），不是英文词数。超长则截断并强制保留 </s>。 新闻语料上 48–64 较常见；短句试跑可用 32。比 tiny 的默认 20「词」更宽松，因为子词切分后序列往往更长。

目标端最大子词数 max_tgt_len（默认 64）

教师强制序列上限；过长截断。推理另见 max_decode_len。

联合 BPE 词表大小 vocab_size（默认 8000）

替代 tiny 的 min_freq。中文字符集大时，若设定值小于「必须覆盖的字符 + 特殊符号」，SentencePiece 会失败——本项目会自动尝试抬升到更大词表。

  • 过小：切得太碎或训练失败（已做兜底）。
  • 过大：嵌入矩阵变大、稀有片统计不足。
  • 快速试跑常用 4000；Jetson / 新闻常用 6000–8000。

验证 / 测试比例 val_ratio / test_ratio（默认各 0.02）

在展开方向之后的样本上划分（互译时验证集里会同时有两个方向）。合计须 < 50%。 大数据集上 2% 已够；小数据可略增以降低 BLEU 噪声。测试集仍不参与选模。

随机种子 seed（默认 42）

控制抽样、划分与初始化。与 tiny 含义相同。

二、模型结构参数

模块组成与 tiny 同类（手写 Enc–Dec，非 nn.Transformer）。差异主要在词表与嵌入共享方式，以及 Web 默认更大。

模型宽度 d_model（默认 512）

须被 n_heads 整除。Web 全局默认 512 偏「完整体」；在 Jetson 上请改用预设（128 / 256），否则易慢或 OOM。 tiny 教学默认是 256。

注意力头数 n_heads（默认 8）

常见搭配：128/4、256/4、512/8。本项目验证页不展示交叉注意力热力图（tiny 有）；头数主要影响容量与速度。

编码器 / 解码器层数（默认各 6）

默认比 tiny 的 3+3 更深。小数据或边缘设备用 2+2 / 4+4 更合适（见预设）。

前馈宽度 d_ff（默认 2048）

惯例约 4 × d_model。参数与显存大户；OOM 时优先降 d_ff / batch_size / 层数。

Dropout dropout（默认 0.1）

与 tiny 相同角色。互译数据相当于「翻倍」时，过拟合压力略小于同规模单向小语料，但仍建议保留 0.1。

Pre-LN norm_first（默认开启）

与 tiny 一致：更深时更好训。

激活 activation（默认 gelu）

gelu / relu。保持 GELU 即可。

共享输出层权重 tie_embeddings（默认开启）

输出投影与（联合）嵌入共用权重。双语大词表时省参更明显，建议保持开启。

三、训练参数

训练轮数 epochs（默认 30）

配合 patience 早停。快速试跑 8 轮；Jetson 预设 20 轮。

批大小 batch_size（默认 64）

句对数 / 步。无 tiny 的长度分桶，长句 batch 更吃显存——Jetson 上常用 16。OOM → 先减 batch。

峰值学习率 lr（默认 5e-4）

略低于 tiny 默认 7e-4（默认模型更大）。不稳就降 lr 或加长 warmup。

学习率计划 schedule（默认 cosine）

cosine / inverse_sqrt / constant，语义与 tiny 相同。inverse_sqrt 在本实现里会归一化到峰值约等于所填 lr。

预热步数 warmup_steps（默认 4000）

默认按「完整体、较多总步数」设定。短训必须改小（快速预设 200；Jetson 2000），否则大半训练仍在爬升学习率。

权重衰减 weight_decay（默认 0.01）

AdamW 解耦衰减，与 tiny 相同。

标签平滑 label_smoothing（默认 0.1）

与 tiny 相同。实现上对本项目损失为「token 平均」的平滑 NLL。

梯度裁剪 grad_clip（默认 1.0）

全局范数裁剪；0 = 关闭。

早停耐心 patience（默认 5）

验证平均 BLEU连续若干轮未刷新最佳则停。tiny 默认 0（不早停）；本项目默认更积极，避免长训空转。

混合精度 AMP amp（默认开启）

tiny 没有此项。仅在 CUDA 上生效；用 torch.amp GradScaler。省显存、通常更快；若遇数值问题可关掉对比。

设备 device（默认 auto）

auto / cuda / cpu。顶栏 GPU 条与 tiny 相同（Jetson sysfs + nvidia-smi）。

日志间隔 log_every（默认 50）

训练进度条 postfix 刷新间隔（步）。曲线点仍按内部 STEP_EVERY（约每 10 步）记录。

四、解码参数

默认束宽 beam_size（默认 4）

写入配置，供验证页默认；训练过程中的验证仍用贪心（快）。交互翻译可在页面上改束宽。

最大解码长度 max_decode_len（默认 80）

推理时最多生成的子词步数（含起止）。可比 max_tgt_len 略大，避免译文被截断。tiny 大致用 max_tgt_len + 余量。

预设分别改了什么

预设要点适合
快速试跑 cmn-eng、both、1.5 万句、d=128、2+2、vocab=4k、8 轮、batch=64 确认互译流程、曲线、GPU；数分钟量级
Jetson 互译 news-commentary、both、最多 8 万句、d=256、4+4、batch=16、20 轮 边缘设备上认真训一版互译
仅英→中 / 仅中→英 把 direction 设为单方向（其它跟默认） 对照「互译 vs 单向」或只要一个方向
不要直接点「检查配置」后不改就用全局默认开训 Web 里 TrainConfig 默认偏大（512 / 6+6）。在 Jetson 上务必先点预设，或手动降容量。

训练和验证时看什么

指标含义怎么读
训练损失标签平滑 NLL应下降；不降 → lr / 数据 / 方向标签是否搞反
验证损失 / ppl每轮验证训练降、验证升 → 过拟合
BLEU（平均）选 best 的依据both 时为两方向算术平均
BLEU 英→中 / 中→英分方向 sacrebleu看互译是否偏科；某一侧崩了优先查该方向数据与长度
测试 BLEU结束后用 best 贪心评测最终报告；不作早停
GPU 使用率顶栏与 tiny 相同读数来源

与 tiny 的字级 BLEU 不可横比。同一项目内用同一 direction 与语料对比才有意义。

验证页：方向、贪心与束搜索

  • 先选方向再输入：英→中输入英文；中→英输入中文。方向与标签必须一致。
  • 贪心 (beam=1)：快，适合扫测试集。
  • 束搜索 (4/8)：通常略好、更慢。

本页没有交叉注意力热力图（tiny 验证页有）。要对齐可视化请用模型实验；本页聚焦双向译文与 BLEU。

调参建议（相对 tiny 的额外注意）

  1. 先「快速试跑」确认两个方向都能出字（验证样例里应能看到 en2zh / zh2en）。
  2. 再「Jetson 互译」或自备配置；一次只改数据规模 / 宽度层数 / 学习率之一。
  3. 互译一侧差、一侧好 → 查该方向长度截断是否过狠、简繁是否统一。
  4. OOM → batch↓、max_*_len↓、层数或 d_ff↓、确认 AMP 已开。
  5. 短训却用很大 warmup_steps → 学习率长期爬升，BLEU 起不来；按总步数的 5%–15% 设预热。
  6. 需要热力图或字级课内 Demo → 回 模型实验；需要 CLI / 互译 / BPE → 留在本页。

命令行对照

Web 与 CLI 共用 mt/。设备上示例：

cd ~/deep_learning/project/bilingual_mt
source ~/deep_learning/.venv/bin/activate
export PYTHONPATH=.
python -m mt.cli prepare -c configs/jetson.yaml
python -m mt.cli train   -c configs/jetson.yaml
python -m mt.cli eval jetson --split test
python -m mt.cli translate <run名或路径> -d en2zh -t "Hello"
python -m mt.cli translate <run名或路径> -d zh2en -t "你好"
