实验 14 纯 NumPy，约 1–2 分钟 Q / K / V

注意力机制：按键查值

第 13 课在编码器–解码器里用过注意力，但公式藏在 GRU 旁边。 本课把它单独拿出来：Query 去问，Key 来应，Value 被取走。缩放点积注意力就是 Transformer 里的那一步； 和一个“把所有槽位平均掉”的基线对照，能直接看见软查找在做什么。

入口 lessons/14_attention.py · 实现 src/dllab/attention.py（scaled_dot_product_attention / LookupNet / gradient_check）

软查找：权重和为 1

这个实验要回答什么

  1. 注意力里的 Query、Key、Value 分别扮演什么角色？
  2. 分数为什么要除以 √d，再做 softmax？
  3. 把所有记忆平均掉，和只盯住匹配的键，差别有多大？
  4. 学会以后，注意力权重会不会集中在正确答案所在的槽位？

Query / Key / Value

Q = q W_Q                         查询（本课里来自“要找的键”）
K = X W_K ,  V = X W_V            每个槽位各有一把钥匙和一份内容
score = Q Kᵀ / √d
α     = softmax(score)            对槽位维归一化，和为 1
context = α V                     按权重取出的内容

第 13 课的 Bahdanau 注意力用 v · tanh(h_s W_a + h_t U_a) 打分；这里改成点积，少一组参数，也是 Transformer 的写法。代码在 scaled_dot_product_attention 与 LookupNet（mode="attention"）。

为什么除以 √d

若 Q、K 的坐标大致独立、方差约 1，则点积的方差大约是 d。d 一大，softmax 就会变得又尖又容易饱和，梯度几乎为零。除以 √d 把分数的尺度拉回大约 1，训练更稳。本课隐藏维是 32，有没有缩放都能学会；习惯上仍写上这一步。

实验：按键查值

  • 键有 16 种，值有 8 种。每条样本抽出 4 / 8 / 16 个槽位，键在样本内互不相同，值随机。
  • 再随机挑一个键当查询，标签是它对应的值。随机猜对率 = 1/8 = 12.5%。
  • 两种模型嵌入维都是 32：平均池化把槽位取平均后与查询拼接再分类；注意力用上面的 Q/K/V 软查找。
  • Adam（lr 4e-3，余弦衰减），批大小 64，梯度裁剪到 1。槽位 4 / 8 / 16 分别训练 400 / 600 / 900 步。测试集各 500 条，缓存在 data/14_attention/。

平均池化为什么不够

平均值里每一份内容的权重都是 1/T。T 变大时，匹配项被稀释，分类器很难从糊成一团的向量里读出正确的值。注意力则可以在匹配键上接近权重 1，其余接近 0——等价于一次可微的查表。

测试准确率。Jetson（192.168.0.110）实测，固定随机种子。随机猜对率 12.5%。一条 16 槽样本：查询键 7，目标值 4，注意力在匹配槽上的权重约 0.92。

通过标准梯度检查相对误差全部 < 1e-4；4 个槽位时注意力准确率 ≥ 90%；16 个槽位时注意力 ≥ 95%，平均池化 ≤ 40%。

自己改一改

  • 把 SLOT_SIZES 加上 32，看平均池化是否更接近随机猜，注意力是否仍能整表查对。
  • 去掉 scaled_dot_product_attention 里的 / √d，对比训练曲线是否更容易抖。
  • 把值的种类 N_VALUES 改成 2，任务变简单：平均池化在短记忆上也可能过关，对照会变弱。
